Issen Fleet — Dependency Layering & Release Order

ADR-0006 · publish bottom-up (leaves first); depend top-down · a crate publishes after every fleet crate it depends on

Release / publish — bottom-up

  • • Publish a tier fully before merging any crate in the tier above.
  • • Applies to release-plz PR sweeps, manual cargo publish, and convergence bumps (the memf 0.3.1 / engine 0.1.5 waves).
  • • Caret reqs (^0.2) soften but don't remove the rule — a crate needing the bumped version fails until it lands.
  • • crates.io throttles updates to existing crates — pace large batches ~3 min apart.

Dependency — top-down

  • • Each crate depends only on tiers below it.
  • • PARSER never imports CONTAINER / FILESYSTEM / PAGING — it accepts Path or &[u8].
  • • CONTAINER depends on FOUNDATION only.
  • • Unsure where a crate sits? Read its [dependencies] / cargo tree — it publishes after all of them.

Why it matters

  • • Wrong order → the split-graph failure class (E0277/E0308, "failed to select a version").
  • • Bit the fleet 3× this cycle: forensic-vfs 0.7, memf 0.3.1, browser-forensic -storage/-webcache.
  • • Used bottom-up to clear a 44-PR release backlog cleanly.
  • • Companion to ADR-0005 (which crates publish at all) + the release skill (how to cut one).
